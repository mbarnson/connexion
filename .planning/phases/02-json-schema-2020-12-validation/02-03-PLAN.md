  <action>
In `../songviber/server/openapi/songviber-api.yaml`, find every occurrence of `nullable: true` and replace with the proper 3.1 type array pattern.

The pattern is:
```yaml
# Before (3.0 style):
property_name:
  type: string
  nullable: true

# After (3.1 style):
property_name:
  type:
    - string
    - "null"
```

For each occurrence:
1. Identify the original `type` value (string, integer, number, etc.)
2. Remove the `nullable: true` line
3. Replace the single `type: X` with `type: [X, "null"]` (YAML array syntax)
4. Preserve all other properties (format, description, etc.)

Known occurrences (~16 based on grep):
- date-time fields (type: string, format: date-time, nullable: true) -- several in DeviceInfo, GenerationJob, Track schemas
- string fields (preset_id, vibe_text, next_cursor) -- in GenerationJob, PaginatedJobs, PaginatedTracks
- number fields (total_duration) -- in GenerationJob
- integer fields (days_until_deletion) -- in Track
- uuid fields (type: string, format: uuid, nullable: true) -- in HealthResponse

For fields with format specifiers, keep the format:
```yaml
# Before:
completed_at:
  type: string
  format: date-time
  nullable: true

# After:
completed_at:
  type:
    - string
    - "null"
  format: date-time
```

IMPORTANT: Quote "null" in YAML to prevent it being parsed as null value. Use either `"null"` or `'null'`.

Verify the spec still has `openapi: 3.1.0` at the top (do not change version).
